# Build system

## Executive Summary

- `lwpt build` is the single root entry point. Bare invocation builds
  every `[build]` target in `lwpt.toml`; positional names select targets.
- Development is the default; `--mode release` selects release settings.
- Every binary lands under `build/`, which is gitignored.
- `source/units/Version.inc` is generated by a `prebuild` hook from the
  manifest — the manifest is the single source of truth for the version.

## Entry point

```bash
lwpt build                        # dev build, every target
lwpt build wasmlight              # one target
lwpt build wasmlight wasmbench    # several
lwpt build --mode release         # release settings
lwpt build --clean                # force a full rebuild
lwpt build --jobs 4               # cap concurrent targets
```

Do not invoke `fpc` directly; the one supported form is
`fpc @lwpt.cfg <program>.pas`, and `lwpt.cfg` is itself generated by
`lwpt install`.

## Targets

| Target | Source | Output |
| --- | --- | --- |
| `wasmlight` | `source/apps/wasmlight.pas` | `build/wasmlight` |
| `wasmlight-shell` | `source/apps/wasmlight-shell.pas` | `build/wasmlight-shell` |
| `wasmbench` | `source/apps/wasmbench.pas` | `build/wasmbench` |
| `wasmspec` | `source/apps/wasmspec.pas` | `build/wasmspec` |

Test programs are not `[build]` targets — `lwpt test` discovers, compiles,
and runs `source/units/*.Test.pas` independently. Release archives are
packed by `scripts/pack-release.pas` after `lwpt build`; they are not a
`[build]` entry. See [deployment.md](deployment.md).

## Compiler settings

All project-wide directives live in `source/units/Shared.inc`, included by
every unit and program. Delphi mode, `{$H+}`, and the dev/release split:
release (`-dPRODUCTION`) turns on inlining and turns off overflow, range,
stack, and object checks; development turns them all on. Never repeat
these directives per unit, and never add a second include with a
different baseline.

## Generated version constant

```toml
[prebuild]
stamp-version = { command = "instantfpc",
                  args = ["scripts/stamp-version.pas"],
                  inputs = ["lwpt.toml"],
                  output = "source/units/Version.inc" }
```

LWPT 0.6 runs lifecycle hooks as explicit commands, so the manifest selects
`instantfpc` and passes `scripts/stamp-version.pas` as its first argument. The
script writes
`PROGRAM_VERSION` from `[package].version` in `lwpt.toml`, or from
`$WASMLIGHT_VERSION_OVERRIDE` when set — which is how a release build
stamps the git tag into the binary. `Wasm.Core` includes the result.

The same hook is registered under `[pretest]`, because the test programs
compile `Wasm.Core` too.

`Version.inc` is committed even though it is generated, so a fresh clone
compiles before any hook has run. Never hand-edit it: change the manifest
version and let the hook restamp.
